# セキュリティレビューチェックリスト

PRレビューおよびリリース前レビューで使用する。該当しない項目は `N/A` と理由を記載する。自動化済みの項目はCIログへのリンクで代替可。

## 認証・認可

- [ ] **認証**: パスワードハッシュ、セッション/JWT の有効期限・失効、多要素（要件がある場合）が設計どおりか
- [ ] **認可**: リソース単位のアクセス制御（IDOR 防止）、最小権限、管理操作の保護が一貫しているか
- [ ] **JWT/OAuth**（利用時）: 署名・`aud`/`iss` 検証、リフレッシュトークンの保管、CSRF と組み合わせた場合の方針が妥当か
- [ ] **機密情報**: シークレットがコード・ログ・エラー応答に含まれないか

## 入力検証

- [ ] **SQLインジェクション**: パラメータ化クエリ/ORMの正しい利用、動的SQLの有無と隔離
- [ ] **XSS**: 出力エスケープ、CSP・テンプレートエンジンの安全な利用（HTML挿入箇所の洗い出し）
- [ ] **インジェクション全般**: コマンド、LDAP、パス、テンプレート等の危険API利用の有無
- [ ] **ファイルアップロード**: 拡張子/MIME/サイズ制限、保存先の公開範囲、実行可能ファイルの拒否

## データ保護

- [ ] **転送中**: HTTPS の強制、適切な TLS 設定（中間者・ダウングレード）
- [ ] **保存時**: 必要なフィールドの暗号化、鍵管理（KMS/環境変数の取り扱い）
- [ ] **PII**: 収集最小化、保持期間、マスキング、ログ・ダンプへの漏えい防止、越境転送の要否

## 依存関係・サプライチェーン

- [ ] **脆弱性スキャン**: `npm audit` / OSV / Snyk 等の結果を確認し、許容できないFindingに対応したか
- [ ] **依存の信頼性**: 新規依存の必要性、メンテ状況、サプライチェーンリスクの判断記録（[DECISIONS.md](../06-reference/DECISIONS.md) またはチームの設計判断ログ）

## API・Web 全般

- [ ] **レート制限・DoS**: 認証エンドポイントや高コストAPIの保護
- [ ] **CORS・CSRF**: ブラウザ経由の操作で不適切な緩和になっていないか
- [ ] **エラー応答**: スタックトレースや内部構造がユーザー向けに露出しないか

## AIエージェント運用

コーディングエージェント・レビューエージェントに書込や実行を任せているプロジェクトで確認する。背景と層の分担は [ガードレール3層構造「AIへの指示の信頼境界」](./GUARDRAILS_THREE_LAYERS.md#aiへの指示の信頼境界) を参照。

- [ ] **命令の範囲**: 命令として扱う範囲（利用者の指示・対象 Issue 本文・合意した記録節）が AI 設定ファイルに書かれ、Issue 本文中の引用・転記部分と外部の文章は情報として扱われるか
- [ ] **統合ブランチの保護**: 統合ブランチへの直接 push がホスティング側のルールで止まっているか（エージェントの確認ダイアログに頼っていないか）
- [ ] **トークンの権限**: エージェントが使うトークン・認証情報の権限が最小か（CI ワークフロー定義の書き換え、シークレットの読み出しに至る経路を含む）
- [ ] **書込経路の限定**: ホスティングへの書込経路（MCP・CLI・API）が安全な入口に限定され、迂回経路が拒否設定の対象になっているか
- [ ] **防御設定の保護**: 防御設定ファイル（権限設定・hook・AI 設定）の編集が、人の確認なしに通らないか
- [ ] **hook の実行環境**: hook の実行環境（シェル・ランタイム）が全端末で揃い、無い端末で黙って無効になっていないか
- [ ] **通信先の制限**: 実行環境の外向き通信が許可リストで絞られているか（サンドボックス・ネットワーク設定・プロキシのいずれか）
- [ ] **外部取得の経路**: 外部ページ・ファイルの生の内容をそのままコマンドで取得して読む経路が拒否され、要約を介した取得に誘導されるか
- [ ] **確認の限定**: 人の確認を出す操作が、めったに起きない操作（マージ・防御設定ファイルの編集）に限定され、通常作業で確認が増えていないか
- [ ] **転記の禁止**: 外部の文言がメモリ・Playbook・作業状態ファイルへ指示文のまま転記されていないか

## 運用

- [ ] **監査ログ**: セキュリティ関連操作の記録要件を満たすか
